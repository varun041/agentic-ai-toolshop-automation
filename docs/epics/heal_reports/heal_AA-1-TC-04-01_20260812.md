**Failure category:** A — Test code defect
**Root cause:** The "the user is navigated to the {string} page" step (used by AA-1-TC-04-01's logout
redirect assertion) used Playwright's default 5000ms `toHaveURL` timeout. The logout redirect is the
same async session-check-driven navigation already diagnosed in `test_cases_AA-1.md` Drift #4 (~1-2s
under light load, longer under Cloudflare/shared-demo-store load) — a sibling step in the same file,
"the user is redirected to {string}" (used by AA-1-TC-04-03/04-04/05-05), already carries a 15000ms
timeout for exactly this reason. The bump was never applied to this second step definition covering the
same underlying redirect, so it timed out at 5000ms under load while the redirect itself completed
shortly after (confirmed via the post-failure screenshot, which showed the header already reverted to
"Sign in").

**Fix applied:** Raised the `toHaveURL` timeout on this step from the 5000ms default to 15000ms, matching
the sibling "redirected to" step's already-established, already-justified value.
