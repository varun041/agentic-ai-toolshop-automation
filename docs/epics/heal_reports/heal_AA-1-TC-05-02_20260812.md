## Heal Report — AA-1-TC-05-02
**Spec file:** tests/step-definitions/aa-1/aa-14.steps.ts
**Run timestamp:** 2026-08-12T21:30:16Z
**Failure category:** A — Test code defect
**Root cause:** The shared "the user is logged in and navigates to the {string} page" step calls
`ToolshopUi.login()` (which only waits for the SPA route to become `/account`, not for the auth-token
write to `localStorage` to complete) and then immediately calls `navigateTo(path)`, which does a HARD
`page.goto()` full reload. Under load, the reload can fire before the token write lands in
`localStorage`; the freshly-reloaded app then reads an empty token and renders logged-out. The scenario
hung until Cucumber's 30000ms step timeout fired mid-navigation. The post-failure screenshot confirmed
this: the page was on the logged-out home screen ("Sign in" visible in the header), not mid-load on
`/account/profile` as a simple slow-page-load would show.

**Fix applied:** Added an `expect.poll` wait for `localStorage.getItem('auth-token')` to become non-null
(5000ms timeout) immediately after `login()` returns, before doing the hard `navigateTo(path)` reload —
eliminating the race rather than just extending a timeout around it.
